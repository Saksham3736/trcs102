## What is a Chatbot?

A chatbot is a software application designed to communicate with users through natural language.

Instead of navigating menus or filling out lengthy forms, users simply send a message describing what they need.

The chatbot then processes the request and returns an appropriate response.

Examples include:

- Customer Support Bots
- Banking Assistants
- Food Ordering Bots
- Travel Assistants
- Parking Management Bots
- AI Assistants

---

## High-Level Workflow of the Finlo Chatbot

During the session, the senior explained the complete processing pipeline followed by the chatbot.

```
User

    ↓

Types a Message

    ↓

Chatbot Receives Request

    ↓

Message Processing

    ↓

Business Logic

    ↓

Parking Ticket Allocation

    ↓

Response Sent to User
```

Rather than replying immediately, the chatbot first analyzes the request before deciding the appropriate action.

---

## Step 1 – User Sends a Message

Every interaction begins with a user message.

Example:

```
"I want to book a parking slot."
```

The chatbot receives this message as input.

At this stage, it simply has raw text provided by the user.

---

## Step 2 – Message Processing

The next stage involves processing the received message.

```
Raw Message

    ↓

Processing

    ↓

Useful Information
```

The chatbot attempts to understand what the user is requesting.

Examples of useful information may include:

- Type of request.
- Relevant keywords.
- Required action.
- Additional details provided by the user.

The session emphasized that this stage is responsible for interpreting the user's intent before any business logic is executed. :contentReference 

---

## Step 3 – Business Logic

Once the request has been understood, the chatbot forwards the processed information to the application's business logic.

Conceptually,

```
Processed Request

    ↓

Business Rules

    ↓

Decision
```

This stage determines what operation should be performed based on the user's request.

For example,

if the request relates to parking,

the system checks the necessary information before generating a parking ticket.

---

## Step 4 – Parking Ticket Allocation

After completing the required processing,

the chatbot automatically allocates a parking ticket.

```
Business Logic

    ↓

Parking Allocation

    ↓

Ticket Generated
```

Instead of requiring manual intervention,

the system performs the allocation automatically based on the processed request.

This demonstrates how conversational interfaces can automate repetitive operational tasks.

---

## Step 5 – Response Generation

Finally,

the generated result is sent back to the user.

```
Parking Ticket

    ↓

Response Generated

    ↓

Displayed to User
```

The conversation is completed once the user receives the chatbot's response.

---

## Complete Chatbot Workflow

The entire architecture discussed during the session can be summarized as follows.

```
  User
    ↓
Send Message
    ↓
 Chatbot
    ↓
Process Message
    ↓

    ↓

    ↓
```

## Ordinary Search vs Structured Search

A normal Google search might look like:

```
Need a developer
```

This often returns millions of unrelated results.

Instead, professional developers narrow the search using **search operators**.

---

## The `site:` Operator

The first operator discussed during the session was:

```
site:
```

It limits search results to a specific website or domain.

General syntax:

```text
site:website.com keyword
```

Example:

```text
site:linkedin.com developer
```

This tells Google to search **only within LinkedIn** for pages containing the word **developer**.

---

### Visual Representation

```
Google
↓
Search Only
↓
linkedin.com
↓
Relevant Results
```

Instead of searching the entire web, Google restricts the search to a single website.

---

## Exact Phrase Search

The senior also demonstrated the use of **quotation marks (`" "`)**.

General syntax:

```text
"exact phrase"
```

Example:

```text
"Need a developer"
```

Without quotation marks,

Google searches each word independently.

With quotation marks,

Google searches for the **entire phrase exactly as written**.

---

### Example

Without quotes

```
Need developer
```

Google may return pages containing:

- Need
- Developer
- Needed
- Development

With quotes

```
"Need a developer"
```

Google attempts to match the complete phrase.

This produces much more focused results.

---

## Combining Multiple Operators

One of the most useful demonstrations combined multiple search operators into a single query.

The example shared during the session was:

```text
site:linkedin.com "Need a developer" "@gmail.com"
```

Let's understand each component.

| Component | Purpose |
|-----------|---------|
| `site:linkedin.com` | Restrict search to LinkedIn. |
| `"Need a developer"` | Match the exact phrase. |
| `"@gmail.com"` | Search for pages containing a Gmail address. |

By combining these operators, the search becomes highly specific.

---

### Search Flow

```
Google Search
↓
Limit to LinkedIn
↓
Find Exact Phrase
↓
Locate Gmail Address
↓
Highly Filtered Results
```

This demonstrates how multiple search operators can work together to refine search results.
